# CareerCraft · 项目决策模拟器

> 信息不完全、多目标约束下的复杂项目决策能力训练平台

CareerCraft 是面向管理科学与工程专业的教学实训产品。学生在一个模拟的复杂项目场景中扮演项目负责人，通过访谈 AI 角色、收集信息、验证冲突、建立决策模型并提交决策，最终获得证据化复盘报告。

**不是聊天游戏，不是黑盒打分工具，不是职业培训课。** 核心价值在于训练"信息不完全条件下的结构化决策能力"。

---

## 核心机制

学生完成的决策闭环：

```
接收任务 → 发现信息源 → 访谈与验证 → 建立决策模型 → 提交决策 → 观察后果 → 证据化复盘
```

每一步都有系统机制支撑：

| 步骤 | 机制 | 说明 |
|------|------|------|
| 接收任务 | 场景简报 + L0 公开事实 | 只给背景，不给问题清单 |
| 发现信息源 | 4 个 AI 角色，各持不同信息 | 学生判断先找谁，训练干系人识别 |
| 访谈与验证 | 三层信息分级 + 机会成本 | 每次访谈消耗模拟时间预算，必须取舍 |
| 建立决策模型 | 事实清单 + 硬约束 + 方案比较 | 把"聊天"变成"可分析的决策结构" |
| 提交决策 | 方案选择 + 证据引用 + 应急预案 | 硬约束实时检查但不阻止提交 |
| 观察后果 | 状态变量传导 + 结果规则 | 决策改变项目状态，不同决策不同结局 |
| 证据化复盘 | 结构化日志 + 五维评分 + 反事实分析 | 不只告诉你得了多少分，更告诉你哪里好哪里差 |

## 标杆场景：上线前夜 · 星盘结算

### 场景背景

支付链路 SaaS 产品「星盘结算」计划明日 09:00 上线，配合已签约的市场推广活动。新引擎核心支付接口存在已知缺陷，QA 在 staging 环境复现确认触发阈值为 QPS > 2500。预估活动峰值 3200 笔/秒。学生需要在两个决策节点完成信息收集、方案比较并提交决策。

### 决策节点

| 节点 | 截止 | 内容 | 影响 |
|------|------|------|------|
| D1 中间决策 | 今晚 21:30 | 资源投向：连夜修复 / 灰度准备 / 继续回归 | 锁定 D2 解空间，触发不同信息自动披露 |
| D2 最终决策 | 明早 09:00 | 上线方案：Go全量 / Delay / Limited(5%/20%/50%) | 决定最终结果和状态变化 |

### 四个 AI 角色

| 角色 | 姓名 | 不可替代事实 | 立场 |
|------|------|-------------|------|
| R1 技术负责人 | 沈屹 | F-06 修复风险、F-10 灰度开关、F-11 排期明细、F-12 回滚能力 | 风险优先，主张修复或灰度 |
| R2 QA负责人 | 闻笛 | F-04 缺陷阈值、F-07 灰度安全线、F-15 实际产能、F-16 降级方案 | 质量底线，P1 必须修复 |
| R3 运营负责人 | 江照 | F-09 延期损失、F-13 老引擎折中、F-17 用户流失率 | 商业优先，主张按时上线 |
| R4 CEO | 许可 | F-08 总损失110万、F-14 竞品情报 | 战略平衡，关注窗口和长期影响 |

### 三层信息分级

| 层级 | 条数 | 获取条件 | 示例 |
|------|------|---------|------|
| L0 公开 | 5 条 | 初始可见 | 上线时间、活动峰值、延期损失80万 |
| L2 隐藏 | 7 条 | 结构化提问 / 正式询问 / D1自动 | 缺陷阈值2500、回滚5分钟、灰度开关30分钟 |
| L3 高价值 | 5 条 | 信任≥配合 + 沟通动作 | 总损失110万、竞品下周上线、QA产能0.7 |

### 7 条硬约束

| 编号 | 约束 | 违反后果 |
|------|------|---------|
| C-01 | D1 决策窗口 16h | 方案不可执行 |
| C-02 | 研发资源 ≤ 3 人天 | 方案禁止提交 |
| C-03 | 活动不可取消 | 方案不可执行 |
| C-04 | 事故止血 < 15 分钟 | 应急能力不足，决策质量-8 |
| C-05 | P1 缺陷不可带病全量上线 | Go全量标记高风险 |
| C-06 | D2 决策须在 21:30 前提交 | 超时执行默认方案 |
| C-07 | 决策须引用 ≥ 3 条事实证据 | 决策质量-5，幻觉证据-10/条 |

### 五维评分

| 维度 | 权重 | 引擎 | 说明 |
|------|------|------|------|
| 用户洞察 | 20% | 规则引擎 | 按 L0/L2/L3 分值累加，红线事实额外加分 |
| 决策质量 | 25% | 混合 70%规则+30%LLM | 约束检查 + 证据引用 + 方案合理性 |
| 沟通协作 | 20% | 规则引擎 | 角色覆盖度 + 信任变化 + 交叉验证 |
| 商业平衡 | 20% | 规则引擎 | 状态变量 + 隐性损失识别 + 战略意识 |
| 成长反思 | 15% | LLM | 复盘深度和改进方向 |

## 技术架构

```
┌─────────────────────────────────────────────┐
│                 数据层                        │
│         scenario_data.json（真值表）           │
│   17事实 / 4角色 / 7约束 / 6结果规则           │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────┴──────────────────────────┐
│                 交互层                        │
│  Agent 提示词 × 4角色 + 意图分类器             │
│  三层防线：RAG检索 → 结构化提示 → 后处理校验    │
│  关系引擎：四档信任 + 正式询问规则             │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────┴──────────────────────────┐
│               决策与状态层                     │
│  硬约束引擎（7条if-then）                     │
│  状态机（S1连续 / S2离散 / S3连续）            │
│  结果规则引擎（RR-1~RR-6 确定性计算）          │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────┴──────────────────────────┐
│               评估与反馈层                     │
│  结构化日志（全过程埋点）                       │
│  五维混合评分（规则70% + LLM 30%）             │
│  证据化复盘 + 反事实分析                       │
└─────────────────────────────────────────────┘
```

**核心设计原则：状态变化和评分由规则引擎计算，不交给 LLM 推理。** LLM 只负责 Agent 对话生成和复盘辅助评估。即使 Agent 偶尔越界，也不会破坏评分公平性和复盘准确性。

## 快速开始

### 体验 Demo

双击打开 `PM模拟器.html`，浏览器中直接运行，无需安装。完整体验约 30-40 分钟。

### 运行引擎

```bash
cd engine
node index.js
```

引擎会执行一次完整的端到端测试：启动会话 → 访谈角色 → 提交 D1/D2 → 生成复盘报告。

### 自定义场景

编辑 `engine/scenario_data.json`，替换事实、角色、约束和结果规则。引擎模块不需要修改——它们读取数据驱动。
