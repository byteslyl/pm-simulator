# CareerCraft 演示体验手册

> 用途：给验收、路演和大赛汇报使用。本文档记录推荐体验路径、每一步要展示的产品能力、讲解口径和已发现断点。

## 1. 演示目标

让评审看到 CareerCraft 不是普通聊天工具，而是一套训练学生在信息不完整条件下做结构化决策的仿真系统。

核心体验闭环：

```
接收任务 -> 访谈关键角色 -> 捕获证据 -> 消耗行动窗口 -> D1 中间决策 -> D2 六要素工作台 -> 复盘报告 -> 成长反思
```

演示时要突出三件事：

- 信息不是一次性给全，必须问对人、问对问题。
- 每次访谈都有行动窗口成本，学生不能零成本问遍所有人。
- 最终决策必须被证据支撑，复盘报告能解释哪里做得好、哪里有盲区。

## 2. 推荐演示路径

### Step 0 启动

打开本地服务：

```
npm start
```

访问：

```
http://localhost:3001
```

首屏讲解：

- 产品主题是「星盘结算上线指挥舱」。
- 用户扮演项目负责人，需要在有限时间内决定明早是否上线。
- 右侧视觉不是装饰，是训练闭环：角色访谈、证据图谱、风险沙盘、复盘教练。

点击「开始模拟」。

建议打开右侧「演示路线」面板辅助操作：

- 「准备本步」会自动选中推荐角色并填入推荐问题。
- 访谈问题仍需演示者点击「发送」，方便控制讲解节奏。
- D1/D2/报告/反思步骤会自动打开对应界面或预填内容。
- 「标记完成」用于现场跳过某一步。
- 「重置路线」用于重新彩排。

### Step 1 先问 QA，拿质量风险

选择左侧「闻笛 QA负责人」。

输入：

```
作为项目负责人，我需要评估灰度比例的安全性。缺陷的触发阈值、复现条件和QA结论是什么？
```

应展示：

- 对话区出现角色回复。
- 消息下方出现「行动窗口」消耗和新增线索。
- 右侧「证据图谱」沉淀关键线索。
- 「访谈教练」提示下一步应做交叉验证。

讲解重点：

- 信息来自角色职责，不是系统直接发答案。
- QA 提供质量视角，但还不能只听 QA 一方。

### Step 2 问技术负责人，验证回滚与灰度能力

选择「沈屹 技术负责人」。

输入：

```
作为项目负责人，我需要评估应急预案。新引擎如果异常，回滚和切回老引擎需要多久？
```

应展示：

- 新增技术侧线索。
- 若问题引用了 QA 风险，可能出现跨角色验证反馈。
- 行动窗口继续减少。

讲解重点：

- 学生开始把质量风险和技术应急能力连接起来。
- 系统训练的是证据链，不是单点信息记忆。

### Step 3 问运营，获得商业约束

选择「江照 运营负责人」。

输入：

```
作为项目负责人，我需要平衡活动目标。延期会损失什么，活动页有没有折中方案？
```

应展示：

- 商业损失、活动约束或折中方案进入证据图谱。
- 右侧工作台可开始积累“目标、风险、证据引用”。

讲解重点：

- 项目决策不是只看技术风险，也要看活动承诺和用户体验。

### Step 4 问 CEO，补战略总账

选择「许可 CEO」。

输入：

```
运营说延期直接损失80万，我需要算完整总账。80万是不是全部代价？竞品窗口有什么压力？
```

应展示：

- CEO 给出高层视角。
- 对话下方出现跨角色引用或新增线索。
- 业务平衡维度变得更完整。

讲解重点：

- 同一事实在不同角色视角下价值不同。
- 高层不是替学生决策，而是补足战略变量。

### Step 5 提交 D1

点击底部「提交 D1 决策」。

选择：

```
B_灰度准备
```

点击确认。

应展示：

- 系统补充关键线索。
- 当前阶段切换到 D2。
- 行动窗口仍保留之前的消耗记录。

讲解重点：

- D1 是“资源投向”，不是最终方案。
- 选择灰度准备会带来新的信息增量，体现机会成本设计。

### Step 6 做两次收束追问

回到「闻笛 QA负责人」。

输入：

```
基于QPS阈值和预估峰值，灰度比例控制到多少比较安全？今天QA实际回归产能够吗？
```

再选择「许可 CEO」。

输入：

```
为了和高层对齐战略窗口，请确认竞品下周是否会上线同类功能？
```

应展示：

- 行动窗口接近耗尽或耗尽。
- 系统提示进入决策。
- 访谈教练从“继续侦查”转为“整理证据”。

讲解重点：

- 好的学生不是问遍所有问题，而是在窗口内问会改变决策的变量。

### Step 7 提交 D2

点击「提交 D2 决策」。

推荐选择：

```
Limited_20%
```

在工作台填写：

目标：

```
保障支付链路稳定
保留活动收益
为后续放量保留数据依据
```

决策边界：

```
活动不可取消
异常需快速止血
灰度比例必须低于风险承受范围
```

风险：

```
缺陷在高峰流量下触发
回归覆盖不足
延期损失与竞品窗口
```

操作方式：

- 从右侧证据图谱点击或拖入至少 3 条线索到「关键线索」和「证据引用」。
- 在「决策依据」里写：选择中低比例灰度，不全量冒险，也不直接延期；依据来自 QA 阈值、技术回滚、运营损失和 CEO 战略窗口。
- 点击确认提交。

应展示：

- 未填齐时按钮不可提交，体现结构化决策强制约束。
- 填齐后才能提交，体现“不是只选一个按钮”。

### Step 8 查看复盘报告

点击「查看复盘报告」。

应展示：

- 综合评分。
- 五维雷达图。
- 行动窗口使用。
- 证据图谱快照。
- 六要素工作台回放。
- 反事实分析。
- 决策边界校验。

讲解重点：

- 系统不只告诉学生“对或错”，而是解释为什么。
- 反事实分析可以让学生看到不同方案的后果。

### Step 9 提交成长反思

点击「提交反思」。

输入：

```
我一开始容易只围绕缺陷本身追问，但本次决策真正需要同时验证技术阈值、回滚能力、商业损失和战略窗口。更好的做法是先锁定关键信息源，再用已获得的证据跨角色验证，最后把事实、目标、边界、方案、风险和证据引用放进同一个决策结构。下次遇到类似上线风险，我会先建立证据清单，优先追问会改变决策方向的变量。
```

点击提交。

应展示：

- 报告刷新。
- 成长反思维度提升。
- 评分从未反思状态提升到更完整的训练结果。

讲解重点：

- 复盘不是附属功能，它是能力迁移的最后一环。

## 3. 彩排验证结果

已用 API 按上述路径模拟完整流程，结果如下：

- 流程：创建会话 -> 访谈 -> D1 -> D2 -> 报告 -> 反思评分。
- 获取线索：F-01、F-02、F-03、F-05、F-09、F-04、F-07、F-06、F-10、F-13、F-08、F-14、F-12。
- D1：B_灰度准备。
- D2：Limited_20%。
- 决策边界：无违反项。
- 反思前：79.5，C（合格）。
- 反思后：84.5，B（良好）。

## 4. 已发现断点与处理

| 断点 | 影响 | 状态 |
|------|------|------|
| 开始页直接显示后端完整场景描述，提前暴露阈值和峰值 | 削弱信息不完全体验 | 已修复：前端改为不剧透案情简介 |
| D1 选项显示“自动揭示” | 暴露内部机制 | 已修复：改为“补充关键线索” |
| 证据卡显示 L0/L2/L3 | 偏开发口径 | 已修复：改为公开/关键/深层 |
| 普通自然提问容易只拿到少量深层线索 | 演示不够精彩 | 已通过推荐提问脚本规避 |
| 未提交反思时总分偏低 | 容易误以为产品效果一般 | 演示脚本已把成长反思作为最后一步 |

## 5. 演示讲解口诀

一句话定位：

```
CareerCraft 用一个高压上线情境，训练学生在信息不完整、时间有限、角色立场冲突的条件下，完成证据化项目决策。
```

三句能力解释：

- 问对人：不同角色持有不同线索。
- 问对问题：线索需要通过追问、验证和交叉引用浮现。
- 做对结构：最终方案必须进入六要素工作台，并接受复盘评估。

## 6. 下一步优化建议

1. 把复盘报告里的反事实分析做成更强的对比卡片。
2. 把证据之间的关系做成可视化网络，强化“线索板”体验。
3. 继续增强演示模式：增加全流程排练视图和演示者提示词。
